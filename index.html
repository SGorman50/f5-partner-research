1. New OTLP Metrics API: Agentless OpenTelemetry Ingestion into Datadog

Datadog launched a new OTLP Metrics API that allows applications to send OpenTelemetry metrics directly into Datadog without deploying a collector or the Datadog Agent. It supports cloud-managed OTel distributions (AWS ADOT, Azure Monitor OTel Distro) and serverless platforms (Azure Functions, Cloudflare Workers, Vercel) that emit OTLP natively. This expands Datadog's OTel ingestion methods to include agentless direct push via the OTel HTTP Exporter. Metrics land immediately in existing Datadog dashboards and alerts alongside traces and logs.

🔗 datadoghq.com/blog/otlp-metrics-api/
🎯 F5 Relevance F5 NGINX and BIG-IP can emit OpenTelemetry telemetry — this API creates a direct, agentless pipeline from F5 infrastructure into Datadog observability, a strong joint integration story for enterprise customers running F5 in cloud or serverless-adjacent environments.

2. CNM Network Health: AI-Guided TLS, DNS, and Policy Diagnostics for Cloud Networks

Datadog's Cloud Network Monitoring (CNM) added a new "Network Health" capability that correlates real-time flow data, TCP metrics, and cloud configuration to diagnose exactly why service-to-service connections fail. It specifically detects TLS certificate expiration, trust chain failures, and cipher/config mismatches — surfacing root causes and recommended remediation steps. DNS failures (NXDOMAIN, SERVFAIL, timeouts) are correlated with live flow data and resolver context. AI-powered Watchdog insights surface contributing factors and unusual patterns to accelerate MTTR.

🔗 datadoghq.com/blog/cnm-network-health/
🎯 F5 Relevance F5 BIG-IP is a primary TLS termination and SSL offload platform in enterprise networks — a partnership where Datadog CNM Network Health surfaces BIG-IP TLS/cert issues and DNS health in real time would be highly compelling for joint customers, and could integrate with F5's telemetry streaming and NGINX observability exports.
