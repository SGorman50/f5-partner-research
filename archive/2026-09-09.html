CiscoSeptember 8, 2026

Cisco and VMware Detail AI-Ready Private Cloud Fabric with Nexus One and VCF

On September 8, 2026, Broadcom's VMware Cloud Foundation blog described joint work with Cisco to make VCF 9.1 and Cisco Nexus One an AI-ready private-cloud fabric. The design peers VCF workload domains to Nexus One over native BGP EVPN so there is no gateway translation, whether the fabric is run as ACI, NX-OS, or SONiC. VCF 9.1's distributed Transit Gateway moves north-south forwarding onto ESX hosts, and Cilium is called out as an alternative CNI for VKS 3.6+ so eBPF Kubernetes workloads can join the EVPN-VXLAN fabric. The post frames AI training as lossless east-west RoCEv2 traffic and inference/RAG as bursty north-south pulls from object storage outside the cluster.

https://blogs.vmware.com/cloud-foundation/2026/09/08/ai-ready-private-cloud-with-cisco-and-vmware/

F5 Relevance

F5 BIG-IP, NGINX, and Distributed Cloud sit on the north-south path from GPU clusters to object storage and inference consumers. A Cisco/VMware EVPN fabric with distributed transit gateways is a natural insertion point for F5 ADC, WAF, and API security in front of AI endpoints and S3-style data paths.

IntelSeptember 7, 2026

Thales, Microsoft, and Intel Position Independent Trust Boundary for Confidential AI

On September 7, 2026, Thales published a freely readable brief describing a joint confidential-computing control-gate with Microsoft Azure and Intel. The End-to-End Data Protection (E2EDP) design combines Azure Intel TDX confidential VMs, independent attestation via Intel Trust Authority, and customer-controlled keys/policies through Thales CipherTrust so hardware isolation, attestation, and key custody are not all owned by one cloud provider. Thales frames the split trust boundary as a response to GDPR Article 32, DORA, and EU AI Act expectations for banks, healthcare, and government that want to run high-value AI without handing the cloud operator the entire trust chain.

https://www.itsecuritynews.info/unlocking-high-value-enterprise-data-for-confidential-ai/

F5 Relevance

Confidential AI traffic still needs a policy and identity enforcement point outside the TEE. F5 SSL/TLS, identity-aware access, and API security can sit in front of TDX-backed inference and training endpoints, while F5 alliance teams can use the Intel/Microsoft/Thales split-trust story in regulated Secure AI conversations.

NutanixSeptember 8, 2026

Nutanix AHV Gains General Availability for Azure Virtual Desktop Hybrid

On September 8, 2026, Nutanix announced general availability of Microsoft Azure Virtual Desktop Hybrid on Nutanix AHV. Session hosts run on-premises on AHV while the AVD control plane stays in Azure; Azure Arc joins those hosts into Azure so identity, policy, and brokering remain on Microsoft Entra ID. Nutanix was a launch ecosystem partner. The model targets regulated and sovereignty-sensitive desktops that cannot move to public Azure, with optional Nerdio Manager automation for provisioning, patching, and autoscaling. Windows Server multi-session and Windows 11 Enterprise single-session are supported; Windows 11 multi-session remains exclusive to Azure and Azure Local.

https://www.itweb.co.za/article/nutanix-supports-general-availability-of-azure-virtual-desktop-hybrid-on-nutanix-ahv/WnxpE74YymxMV8XL

F5 Relevance

Hybrid AVD puts Entra ID, Azure Arc, and on-prem desktop traffic on the same path F5 already secures with SSL VPN, identity-aware proxy, and BIG-IP APM. F5 can position access, WAF, and network segmentation in front of AHV session hosts so sovereign VDI does not bypass enterprise zero-trust controls.

NvidiaSeptember 8, 2026

NVIDIA Introduces CUDA Rust with Two Tracks for Writing GPU Kernels

On September 8, 2026, NVIDIA's developer blog announced native GPU programming in Rust alongside mature CUDA C++ and CUDA Python toolchains. Two early tracks are cuda-oxide (Rust-to-PTX via Pliron IR and LLVM, alpha) and cutile-rs (published on crates.io and already used in projects such as Hugging Face's Grout and mistral.rs). APIs are still changing; NVIDIA is soliciting feedback via GitHub Discussions and Discord and pointed to RustConf 2026. The move extends CUDA's language surface as Hugging Face-related Rust inference stacks grow inside NVIDIA's ecosystem.

https://developer.nvidia.com/blog/introducing-cuda-rust-two-tracks-for-writing-gpu-kernels/

F5 Relevance

New CUDA language runtimes change how inference services are packaged and exposed. F5 AI traffic management, API gateway, and Kubernetes ingress remain the front door for Rust-based GPU kernels served as microservices, and the Hugging Face/Grout mention keeps this in the same open-model stack F5 is tracking after the Hugging Face acquisition.

RedHatSeptember 8, 2026

Red Hat OpenShift Adds GA Support for NVIDIA BlueField in the AI Factory

On September 8, 2026, Red Hat said OpenShift now generally supports NVIDIA BlueField DPUs, pairing OpenShift with the NVIDIA DOCA Platform Framework to offload, accelerate, and isolate infrastructure services onto DPU silicon. The post cites up to 30% of host CPU wasted on packet routing and security policy, and positions BlueField as a foundation of the Red Hat AI Factory with NVIDIA for agentic inference and 5G RAN. OVN-Kubernetes/Open vSwitch can run on the DPU at line rate, reclaiming host cores, enforcing hardware tenant isolation, and keeping GPU pipelines fed by removing network bottlenecks.

https://www.redhat.com/en/blog/nvidia-bluefield-security-and-acceleration-arrive-red-hat-ai-factory-nvidia-and-red-hat-openshift

F5 Relevance

DPU-offloaded OVN and in-silicon isolation change where F5 inserts ADC, WAF, and API security in OpenShift AI factories. F5 can partner on the remaining north-south and ingress path, BIG-IP Next for Kubernetes, and Secure AI messaging that complements BlueField rather than competing with host-CPU security agents.
